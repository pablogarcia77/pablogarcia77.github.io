# AGENTS.md

## Scope

These instructions apply to the whole repository.

## Repository shape

- This repository is a static portfolio site intended to be served directly from the repository root, including GitHub Pages.
- The checked-in files are generated/static output, not the original Next.js application source.
- There is no `package.json`, lockfile, framework config, source directory, or test suite in this checkout.
- Keep `.nojekyll`; it is required so GitHub Pages serves `_next/static/*` paths unchanged.

## Important paths

- `index.html` and `index.txt`: home route (`/`).
- `404.html` and `404/index.html`: 404 route output.
- `contact/`, `copyright/`, `my-story/`, `privacy-policy/`, `projects/`: static route directories with `index.html` and matching Next/RSC `index.txt` payloads where present.
- `_next/static/`: generated Next.js runtime, page chunks, CSS, fonts, and build manifest. Files are hashed and minified.
- `assets/images/`: portfolio images and icons.
- `assets/pdf/`: downloadable CV PDFs.
- `manifest.json`: PWA manifest metadata.
- `static/favicon.ico` and root `favicon.ico`: favicon assets.

## Technology detected

- Generated by Next.js static export using React chunks under `_next/static/chunks/`.
- Tailwind CSS v3.4.4 is embedded in `_next/static/css/b1c48085b8a8a0ab.css`.
- The HTML includes Google Analytics (`G-N8ZTB9NPSP`) and Google AdSense (`ca-pub-6427962014782182`) scripts.
- The site uses both root-relative URLs (`/_next/...`, `/assets/...`) and, on the root page, some relative URLs (`./_next/...`). Preserve the current style for the file you edit.

## Change policy

- Prefer editing the original upstream Next.js source and regenerating this static output. If the source is not available, state that limitation before making broad UI/content changes.
- Do not hand-edit `_next/static/chunks/*` or hashed CSS unless the task is a narrow emergency patch. Those files are generated, minified, and cache-keyed by filename.
- If a hashed asset changes, either preserve the existing filename intentionally or update every reference to the new filename.
- For page content edits in generated output, update all route representations that expose the same content: the visible `index.html`, the matching route `index.txt` when present, and any duplicate 404 output.
- Keep root and nested route pathing consistent. Root `index.html` currently uses `./_next/...`; nested routes use `/_next/...`.
- Do not introduce build scripts, package managers, or framework config unless restoring the real source project is part of the task.
- Do not remove generated files just because they look unused; Next.js static output and GitHub Pages routing depend on exact filenames.

## Existing issues to avoid misattributing

- Several pages already reference missing local routes `/blog` and `/repo-inspector/`.
- Several pages already contain the typo link `javasript:void(0)`.
- `manifest.json` already references missing icons `./icon512_maskable.png` and `./icon512_rounded.png`.
- Page titles and descriptions were normalized to `Pablo Garcia`; preserve that branding unless the task explicitly asks for another rename.

## Verification

- There is no repository-native build or test command.
- For static-site checks, serve the root directory and inspect the affected route in a browser or with HTTP requests.
- Minimal smoke command: `python3 -m http.server 8000`, then open `http://127.0.0.1:8000/` and each changed route.
- For link/reference checks, use a script that parses local `href` and `src` values; account for known pre-existing missing links listed above.
- For JSON-only changes, validate with `python3 -m json.tool manifest.json`.

## Editing guidelines

- Use parser-aware or scripted edits for generated HTML where possible; many files are minified into very long lines.
- Keep HTML valid, preserve required meta tags, and avoid formatting churn in generated files.
- Optimize static assets before adding them. Prefer WebP for photos and PNG/SVG only when the current asset type requires it.
- Keep PDFs under `assets/pdf/` and public images under `assets/images/`.
- After changing visible UI, verify the actual rendered page, including desktop and mobile widths when layout is affected.
